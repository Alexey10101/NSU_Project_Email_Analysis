# Обучение HTML-модели и CatBoost

Для работы нужен обычный CPython 3.11 или новее. В текущем проекте основное `.venv` переведено на CPython 3.12: MinGW-окружение не подходило для готового пакета CatBoost.

Команды ниже запускаются из корня проекта. В PowerShell используй `& .\.venv\Scripts\python.exe` вместо `python`, если окружение не активировано.

```text
python -m pip install -r training/requirements.txt
```

Файлы разложены так:

- `build_table.py` собирает признаки и проверяет разбиения.
- `train_boosting.py` обучает CatBoost и калибрует оценку на validation.
- `data` содержит CSV с признаками и JSON с описанием таблицы.
- `reports` содержит метрики, порог и важность признаков.
- `logs/catboost` содержит журналы текущего обучения.
- `logs/legacy_catboost` содержит старые журналы, сохранённые для истории.
- обученные модели, их описание и калибровки находятся в `models` в корне проекта.

## HTML-модель

SpamAssassin содержит реальные HTML-письма, но не содержит парных ИИ-версий. Метки spam/ham не используются как метки ИИ. PASTED подходит для текста, но не для обучения HTML-классификатора.

Сначала запусти свою локальную LLM с OpenAI-совместимым API. Затем создай пары:

```text
python scripts/build_html_dataset.py --base-url http://127.0.0.1:1234/v1 --model ИМЯ_МОДЕЛИ --limit 120
python analysis/html_analyze.py --train
```

Если в локальном API доступна ровно одна модель, `--model` можно не указывать. Ключ при необходимости читается из переменной окружения `LOCAL_LLM_API_KEY`, а не из исходников. Внешние адреса и внешние перенаправления запрещены. Генератор не скачивает и не запускает LLM самостоятельно.

В `datasets/HTML_AI/data` сохраняются оригиналы и реальные ответы модели. При неудачной генерации готовые ответы остаются в `generation_cache`, чтобы следующий запуск не повторял работу. Ссылки, изображения и объём текста проверяются автоматически; смысл и факты всё равно нужно проверить вручную. Интервалы изменений вычисляются сравнением оригинала с ответом модели. Близкие письма пока проверяются упрощённо: нормализация пробелов, чисел и проверка хешей не заменяют полноценный поиск похожих кампаний.

Модель, калибровка и отчёт сохраняются в `models/html_classifier.json`, `models/html_calibration.json` и `training/reports/html_metrics.json`. Без парного набора рабочая HTML-модель не создаётся. Проценты без обученной модели не подставляются.

```text
python analysis/html_analyze.py письмо.eml --output результат.json
python analysis/html_analyze.py папка_писем --output результаты.json
```

Результат содержит признаки, индекс от 0 до 1, проценты, вердикт и объяснение. Порог можно изменить через `--threshold`. Интервалы `html_ai_evidence` показывают элементы, участвующие в расчёте признаков; это не точная символьная локализация ИИ-правок. Если в письме нет HTML, возвращается статус `no_html`. Повреждённое письмо не останавливает пакетную обработку.

## CatBoost

```text
python training/build_table.py
python training/train_boosting.py
python analysis/boosting_analyze.py письмо.eml --output результат.json
```

После подготовки HTML-пар можно собрать общий набор:

```text
python training/build_table.py --dataset datasets/PASTED/data datasets/HTML_AI/data
python training/train_boosting.py
```

Таблица содержит исходные признаки, а не готовую оценку старой модели: иначе её обучающие данные могли бы попасть в тест нового классификатора. Пары и дополнительные версии остаются в одной группе. Веса компенсируют число вариантов. Порог и калибровка подбираются на validation, test используется только для итоговых метрик.

Сейчас это CatBoost по доступным признакам, а не готовый ансамбль всех четырёх моделей из плана. На PASTED обучается только текстовая часть. Для HTML-признаков нужны как минимум 20 обучающих групп с HTML в обоих классах. Для объединения нейросетевых оценок и изображений нужен общий размеченный набор и оценки, полученные без утечки данных. Отсутствующие блоки указаны в JSON, их результаты не выдумываются.

Модель CatBoost сохраняется в JSON согласно ТЗ. Рядом находятся `catboost_metadata.json` и `catboost_calibration.json`; они связаны хешем модели. В объяснение входят три наиболее заметных вклада SHAP. Фактические F1, ROC-AUC и FPR находятся в `reports/catboost_metrics.json`; поле `meets_quality_target` показывает, достигнуты ли пороги 0,70 / 0,70 / 0,20. Достижение метрик на текстовом наборе не означает готовность системы на реальной почте.

## Проверка кода

```text
python tests/test_models.py
```

Тесты проверяют некорректные ссылки, отсутствие модели, калибровку, пересечение групп, локальность API и сквозное обучение с загрузкой JSON-моделей. Ручные тестовые пары существуют только во временной папке и не используются для обучения рабочей модели. Их метрики не считаются качеством проекта.
